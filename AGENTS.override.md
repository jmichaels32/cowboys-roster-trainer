# Mobbin-Enhanced Design Exploration

Mobbin is currently authorized for design research.

For significant UI redesigns or new product flows, augment the normal UI Design Workflow with reference research before generating variants.

## Research before ideation

Before designing the four interactive variants:

1. Identify the core user job and interaction problem.
2. Search Mobbin for relevant patterns from strong shipped products.
3. Search by **interaction analogy**, not only product category.

For example, a workout-building flow may learn from:

* playlist creation
* routine builders
* itinerary builders
* task creation
* editing workflows
* creator tools

Inspect several relevant examples rather than copying one product.

Extract:

* recurring information hierarchies
* navigation patterns
* interaction patterns
* primary-action strategies
* progressive-disclosure patterns
* density choices
* useful conventions
* notable approaches worth experimenting with

## Generate directions from principles

Use the research to inspire the four interactive variants.

Do **not** create four copies of Mobbin screens.

The variants should synthesize and reinterpret useful patterns for this product.

Prefer four genuinely different hypotheses, for example:

* a proven conventional approach
* a simplified/minimal approach
* a more interaction-forward approach
* a more distinctive or experimental approach

All directions must still fit the existing product context.

## Preserve the normal workflow

After research:

1. Build four interactive variants directly inside the app.
2. Run and verify them.
3. Give the user the four development routes and concise descriptions.
4. STOP for selection.
5. After selection, promote the winner, test it, refine it, and remove the losers.

Mobbin is a **reference and creativity input**, not the implementation environment and not the final authority on the product.
